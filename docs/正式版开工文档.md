## 3. 架构决策

### 3.1 关键技术约束：file:// 下不能用 fetch 与 ES module

demo 的"双击即开"理念（需求文档 §6）延续到正式版，但 **file:// 协议下 `fetch()` 和 `<script type="module">` 都会被 CORS 拦截**。因此：

- ❌ `fetch('data.json')` —— file:// 下被拦截
- ❌ ES module（import/export）—— file:// 下被拦截
- ✅ **data.js 以全局变量注入**：`const EVENTS=[...]` 独立成文件，普通 `<script>` 按序加载（无 import）
- ✅ 逻辑代码拆普通 script 文件（无 ES module），全局命名空间隔离（如 `window.HTApp` 或 IIFE）

### 3.2 文件结构（正式版）

```
history-timeline/
├── index.html          # 入口，只放结构骨架 + script 引用
├── css/app.css         # 全部样式（从内嵌 <style> 迁出）
├── js/
│   ├── data.js         # EVENTS/CHAPTERS 全量数据（生成器产出，勿手改）
│   ├── common.js       # 工具函数：fmt/stars/matchEvent/wgs84ToGcj02/shuffle
│   ├── timeline.js     # 时间轴视图渲染与交互
│   ├── map.js          # 地图视图（Leaflet 初始化、marker、滑块、播放）
│   ├── review.js       # 复习模式（设置界面、三模式、错题重练）
│   └── app.js          # 顶框/视图切换/搜索/筛选/抽屉/全局状态
├── data/               # （可选）校对中间产物、CHGIS 坐标缓存
├── tests/acceptance/   # Playwright 回归脚本（§4.3）
└── docs/               # 需求文档、开工文档、日志
```

## 5. 经验教训沉淀（demo 三轮回溯，正式版必读）

### 5.1 技术踩坑（已解决，防止复发）

1. **Leaflet 瓦片子域语法**：`{1-4}` 不被 Leaflet 支持（OpenLayers 风格），必须 `{s}` + `subdomains:['1','2','3','4']`，否则 `No value provided for variable` 抛错。
2. **Leaflet opacity/container 位置**：opacity 设在 `.leaflet-tile-pane .leaflet-layer`（每个 tileLayer 自己的容器）；`.leaflet-container` class 加在初始化目标 div **自身**（不是后代）。检查时选对对象。
3. **天地图 key 权限类型（2026-08-01 实测）**：浏览器端 key 只放行浏览器请求（curl 服务器端请求报 `301012 权限类型错误`）——瓦片/JS API 用浏览器端 key，坐标解析类脚本要用**服务端 key**；瓦片验证必须走真实浏览器（Playwright），不能用 curl。
4. **file:// 限制**：fetch 和 ES module 全被 CORS 拦 → 数据用全局变量 script。
5. **事件对象包装一致性**：队列里统一 `{e}` 包装，避免 `s.cur.e.t` 读 undefined（新版函数直用原始数组踩过）。
6. **disabled 输入框死锁**：disabled 元素无法触发 input 事件，不要用它做"点击启用"的起点。
7. **视图切换滚动遗留**：fixed 顶栏 + 展开筛选会遮内容 → 用 sticky；切换视图 scrollTo(0,0)，避免工具栏落在视口外。
8. **"当前章节"判定**：章节标题进入视口 50% 即算当前（35% 会误判）。
9. **Windows 路径坑**：node 的 `/tmp` ≠ Git Bash 的 `/tmp`；bash 内联 `\\s` 转义地狱 → 临时脚本写成文件再跑。
10. **Playwright 选择器**：`:nth-of-type()` 是元素类型级；按钮文本用 `:text-is()`；`$$` 取数组。
11. **验收脚本自身也是代码**：断言要理解产品语义（搜索命中 4 行 = 关联检索特性、错题重练后转 ok = 攻克语义），不是所有"预期≠实际"都是 bug。

### 5.2 流程经验

1. **先静态后浏览器**：数据校验（坐标对齐、字段完整性）用 node 脚本先跑，再 Playwright 交互验收——分层排错。
2. **每次改动全量回归**：demo 每轮验收 7-16 项断言，修 bug 不引入回归。
3. **验收看断言不看截图**：程序化断言可复现、可留作回归资产。
4. **大改先备份**（README §5.4）：批量修改前 `cp` 备份，本次 overview 类大文件无备份吃过亏。
5. **打样数据是资产**：33 条人工写的年份/考点提示，正式版数据生产的**质量基准**（腔调、考点密度照此标准）。
6. **分块提取按块号数字排序合并**：glob 字典序会排成 p1,p10,p11,p2… 导致先解析 p10 报错，合并脚本用 `key=blk_num` 数字排序。
7. **Git Bash heredoc 超 ~3KB 被截断 / 篡改**：写 Python 合并/校验脚本一律用 Write 工具（纯 ASCII），别用 heredoc。
8. **分块 JSON 偶发 key 损坏**：`ëxamTip`（缺字母 e），合并脚本首行做字面替换修复 `txt.replace('ëxamTip', '"examTip"')`，别靠正则。
9. **临时分块用完即删**：`_xxx_pK.json`、合并脚本等本会话产物跑完清理，不留散落文件。
