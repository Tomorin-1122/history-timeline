## 1. 项目概述

### 1.1 定位
- **用途**：考研统考历史学（313）中国古代史复习工具，重点解决"历史事件时间记忆薄弱"问题
- **性质**：自用为主 + 可分享
- **数据来源**：从 my-wiki 知识库一次性抽取（历史事件已发生，无需动态同步）
- **部署**：Vercel（域名 yinyizhuan.cn，子域/子路径待定，本地优先跑）

### 1.2 与 my-wiki 的关系
- 独立子文件夹 `history-timeline/`，与 wiki 本体隔离
- 数据从 wiki 抽取生成 `data.json` 快照，不反向依赖 wiki
- 每个事件保留 `wikiSlug` 字段溯源

## 2. MVP 范围

### 2.1 内容范围
- **仅中国古代史（1840 年之前）**
- 未来功能（不在 MVP）：世界史线、中外对照、制度/人物节点、史料原文、政区边界（时空地图视图为 M7 规划，见 §4.7）

### 2.2 打样策略
| 阶段 | 内容 | 事件数 |
|------|------|--------|
| MVP 打样 | 第 01 章原始社会（纯 era 段）+ 第 04 章春秋（纯 exact 段） | ~30 |
| 铺满全库 | 全部 15 章（先秦/秦汉/魏晋南北朝/隋唐/宋元/明清） | 300-400 |

打样目的：一次性验证时间轴对"精度阶梯两端"（纯时代段 vs 纯精确年）的表现。

### 2.3 数据现状（决定 M1 工作形态）

抽查 `wiki/entities/城濮之战.md` 的结论：

- 实体页 frontmatter **无**年份/朝代字段，"公元前 632 年"埋在正文自然语言里，需正则提取
- `period` 大分期需靠 `tags`（如"春秋时期"）反推，无法直接读取
- `summary` / `cause` / `effect` / `examTip` 四个字段 wiki 中不存在，需 LLM 生成 + 人工校对
- 因此 M1 不是"写个脚本跑一遍"，而是"正则提年份 → LLM 生成文案 → 逐条人工校"三段式

### 2.4 时间精度阶梯（核心设计）
教材实证（朱绍侯《中国古代史》）：
| 章节 | 精确年份 | 模糊词 | 结论 |
|------|---------|--------|------|
| 第 01 章 原始社会 | 0 | 63 | 纯 era 段 |
| 第 02 章 夏商 | 0 | 49 | 纯 era 段 |
| 第 04 章 春秋 | 69 | 41 | exact 为主 |
| 唐代/明清 | 175+/130+ | — | 全 exact，越后越密 |

**越往后年代越精确、事件越密** → 时间轴必须支持"前松后密"的非均匀布局。

## 3. 数据模型

每个事件一个 JSON 对象（`data.json` 数组）。`wikiSlug` 兼任**主键**：全数据集唯一、不随 `title` 改动而变化；`related` 一律存 `wikiSlug` 而非 `title`（title 可改，slug 稳定），避免改名断链。复习模式 localStorage 亦以 `wikiSlug` 为键。

```json
{
  "title": "秦灭六国",
  "year": -221,
  "yearMode": "exact",
  "yearRange": null,
  "dynasty": "秦",
  "period": "秦汉",
  "type": "政治",
  "importance": 3,
  "summary": "秦王政先后灭韩、赵、魏、楚、燕、齐，完成统一，建立中国历史上第一个中央集权王朝。",
  "cause": "战国长期兼并战争的必然结果；商鞅变法奠定强国基础。",
  "effect": "结束诸侯割据，确立郡县制与皇帝制度，奠定大一统格局。",
  "examTip": "注意：灭六国顺序韩赵魏楚燕齐；统一是'远交近攻'策略。",
  "people": ["嬴政", "李斯"],
  "location": "咸阳",
  "tags": ["统一", "战争"],
  "related": ["商鞅变法", "秦末农民起义"],
  "wikiSlug": "秦灭六国"
}
```

### 3.1 字段清单（MVP 17 字段）

| 字段 | 类型 | 必选 | 说明 |
|------|------|------|------|
| `title` | string | ✅ | 事件名 |
| `year` | int | ✅ | 年份（公元前为负数）；`range` 模式下仅作排序缓存 |
| `yearMode` | enum | ✅ | `exact` / `approx` / `era` / `range` |
| `yearRange` | [int,int] | 条件 | `range` 模式的唯一权威取值；其他模式为 null |
| `dynasty` | string | ✅ | 朝代 |
| `period` | enum | ✅ | 大分期：先秦/秦汉/魏晋南北朝/隋唐/宋元/明清 |
| `type` | enum | ✅ | 政治/军事/经济/文化/制度 |
| `importance` | int | ✅ | 3=核心考点 / 2=常考 / 1=了解 |
| `summary` | string | ✅ | 教材学术腔，答题口径 |
| `cause` | string | 推荐 | 前因（一句话） |
| `effect` | string | 推荐 | 后果（一句话） |
| `examTip` | string | 推荐 | 口语复习腔，易错点/记忆钩子 |
| `people` | string[] | 推荐 | 相关人物 |
| `location` | string | 推荐 | 地点/区域 |
| `tags` | string[] | 推荐 | 轻量标签 |
| `related` | string[] | ✅ | 关联事件的 `wikiSlug`（点击跳转/高亮） |
| `wikiSlug` | string | ✅ | 主键；对应 wiki 页面名，全数据集唯一（溯源） |
| `lat` | float | 推荐 | 纬度（WGS84；M7 地图视图用，location 预解析结果） |
| `lng` | float | 推荐 | 经度（WGS84；M7 地图视图用，location 预解析结果） |

### 3.2 importance 评级标准（防人工漂移）

| 星级 | 判定规则 |
|------|---------|
| ★★★（3） | 教材以独立小节/专题讲述，或近 10 年 313 真题设问过 |
| ★★（2） | 教材以独立段落讲述、构成考点但未单列小节 |
| ★（1） | 教材正文顺带提及，仅作背景 |

判定以教材为第一依据（篇幅与独立性），真题为加分确认项；拿不准就降一档，宁缺毋滥。

### 3.3 yearMode 取值
| 值 | 含义 | 示例 | 时间轴表现 |
|----|------|------|-----------|
| `exact` | 精确年份 | 前 221 | 精确坐标 |
| `approx` | 近似年份 | 约前 1600 | 模糊带 |
| `era` | 时代段 | 夏代中期 | 挂在分期条上，不假装精确 |
| `range` | 起止区间 | 前 256~前 221 | 区间条（以 `yearRange` 为准） |

## 4. 界面设计

### 4.1 布局：左年右事两栏
```
────────────────────────────────
  前 221        ▸ 秦灭六国 ★★★ [政治]
               秦王政灭六国完成统一，建立中央集权王朝
────────────────────────────────
  前 213-212    ▸ 焚书坑儒 ★★ [文化]
               ...
────────────────────────────────
```
- 左列：年份刻度（窄栏，等宽字体，纵向扫读形成时间刻度感）
- era 事件左列不显示数字年份，改显朝代名（如"夏代"），斜体 + 灰色，与精确年的等宽数字区分——诚实呈现"时代段"，不假装精确
- range 事件左列显示区间条（前 256~前 221）
- 右列：事件卡片（标题 + 重要度星标 + 类型角标 + 2-3 行摘要）
- 分期分隔带：整行大标题（先秦/秦汉/…）插入其间
- 视觉重心在事件内容，年份列是刻度不是主角

### 4.2 事件详情：右侧抽屉
- 点击卡片 → 右侧滑出详情面板
- 容纳完整字段：summary / cause / effect / examTip / people / location / related
- related 可点击跳转/高亮关联事件
- 优点：浏览列表不丢位置，可放多内容

### 4.3 筛选与导航
- 按 `type`（政治/军事/经济/文化/制度）+ `importance`（★/★★/★★★）过滤
- 分期锚点导航：顶部一排分期名（先秦/秦汉/…），点击滚动到对应分期带——长轴浏览时"跳到隋唐"比筛选更高频

### 4.4 复习模式（独立页面）
- 事件自动生成卡片：正面事件名 / 背面年份+摘要
- 操作：显示答案 / 标记记住 / 标记忘记
- 自动重练错题；状态以 `wikiSlug` 为键存 localStorage（slug 稳定，不怕改名）
- Anki SRS 间隔重复 = 未来功能

### 4.5 视觉风格
- 古籍学术风：纸感底色 + 衬线字体 + 朱砂红点缀
- 不过度拟古，避免装饰性元素
- **待 demo 后由老板拍板**

### 4.6 移动端降级
- 时间轴视图：小屏（<768px）左年右事两栏合并为单栏，年份并入卡片首行（"前 221 · 秦灭六国 ★★★"）
- 筛选与分期锚点收起为顶部抽屉式按钮
- 地图视图：天然适合触屏；小屏隐藏时间轴列表，滑块置底
- 复习模式天然适配手机，是主要移动场景

### 4.7 地图视图（M7 规划，双视图）

时间轴视图的补充视角，同一 `data.json`，顶部 tab 切换（时间轴 / 地图）。

- **范围**：只标注 `yearMode=exact` 的精确时间事件；era / approx / range 事件不上地图（不假装精确）
- **坐标**：`location` → **分时段解析：先秦用高德地理编码解析"今址"，秦汉后用 CHGIS 按年份解析**（CHGIS 覆盖 -222~1911、先秦零覆盖，实测已验证）；不追求考据级精度；解析失败人工补
- **交互**：时间滑块过滤 ±N 年事件（默认 ±50）；点 marker 弹事件卡片（复用抽屉）；点列表/卡片高亮地图点
- **技术**：Leaflet 加载**天地图瓦片**（`vec_w` 底图 + `cva_w` 注记，WMTS 模板，tk 存项目配置）——官方授权合规、**WGS84 免坐标转换**（原高德瓦片 + wgs84→gcj02 方案已废弃，2026-08-01 浏览器实测通过）

## 5. 文案规范

| 字段 | 风格 | 用途 |
|------|------|------|
| summary / cause / effect | 教材学术腔 | 答题语言，可直接背诵 |
| examTip | 口语复习腔 | 易错点、记忆钩子、犀利提醒 |

原则：两层分工，避免通篇单一腔调产生"AI 味"。

## 6. 技术方案

- **纯静态站**：HTML + CSS + JS（无构建，双击即开）
- 数据：**v1.3 修订：file:// 下 `fetch` 与 ES module 均被 CORS 拦截，正式版数据改为 `js/data.js` 全局变量注入（`const EVENTS=[...]`）+ 普通 script 标签按序加载**，不再用 data.json + fetch（详见《正式版开工文档》§3）
- 本地开发：直接打开 index.html；改 data.js 即时生效
- 代码拆分：`js/timeline.js` / `map.js` / `review.js` / `app.js`（从单文件 demo 迁出）
- 地图：Leaflet + 高德瓦片（部署时申请官方 key）

## 9. 风险与注意

1. **年份口径**：夏商周年份教材与断代工程有出入，era 段不写死精确年
2. **wiki 数据质量**：wiki 有 1345 个 stub 空壳，抽取时按实体页真实内容过滤
3. **事件筛选标准**：只收 313 可考事件，细碎年份（即位/卒年等）不收；**战略性迁都（政权存续/战略重心转移标志，如周平王东迁、魏惠王迁都大梁）属考点应收**，仅无考点意义的琐碎迁都不收
4. **人工校对**：抽取后需人工核对年份与 importance 星级（正式版 300-400 条约 10-13h，分批推进）
5. **M1 依赖 LLM 生成 + 人工校**：四个文案字段需生成后逐条校对；打样 33 条可复用为正式版前两批质量基准
6. **related 悬空**：`related` 引用的事件可能未收录进数据集；前端对无匹配 `wikiSlug` 的 related 降级为纯文本显示，不强求成链
7. **file:// 限制**：正式版数据用 data.js 全局变量规避 fetch/ES module 的 CORS 拦截（开工文档 §3.1）
8. **CHGIS 先秦零覆盖（实测）**：CHGIS 数据自 -222 始，先秦地名查不到；先秦坐标统一走高德地理编码"今址"通道，秦汉后仍用 CHGIS

## 10. Demo 打样总结与经验（2026-08-01）

### 10.1 打样成果

- `demo.html`：时间轴打样（33 条手工数据，原始社会 + 春秋两章，同行编写）
- `demo2.html`：三视图完整打样（时间轴 / 地图 / 复习），三轮迭代 Playwright 验收 7-16 项断言全绿

### 10.2 正式版衔接

- 交互设计全部沿用 demo；数据、坐标、代码工程化为正式版替换项
- 详见《正式版开工文档》（docs/正式版开工文档.md）：差距清单 / 数据生产流程 / 架构决策 / 里程碑 F0-F5 / 经验教训

### 10.3 关键经验一句话

1. file:// 下不能用 fetch / ES module → 数据用全局变量 script 注入
2. Leaflet 瓦片子域用 `{s}`（`{1-4}` 不被支持）；opacity 设在 `.leaflet-layer`
3. 坐标必须 wgs84→gcj02 转换（实测西安偏移约 458m）
4. 验收用 Playwright 断言而非截图；断言要理解产品语义（关键词关联检索、错题攻克后转 ok 均为特性）
5. 打样 33 条数据是正式版文案腔调与考点密度的质量基准
6. 视图切换需 scrollTo(0,0)；顶栏用 sticky 避免筛选展开遮内容
